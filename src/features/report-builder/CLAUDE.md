# Report Builder Feature

The bottom toolbar's **Report Builder** button. Report tools are ordinary CEA scripts (core or plugin) whose
`scripts.yml` entry names the HTML report they write (`report: <locator method>`); the backend lists them at
`GET /reports/builders` and serves a written report at `GET /reports/builders/{script}/html`.

## Main API

- `useReportBuilders()` - `[{ name, label, short_description }]` of the report tools.
- `openReport(script, scenarioContext)` - Fetch a report and open it in a new tab (blob URL).
- `OpenReportButton` / `isReportJob(reportBuilders, job)` - "Open Report" for a finished report-tool job, in the
  job-completed notification (`StatusBar`) and `JobInfoModal`.

## Key Patterns

### DO: Launch report tools through the normal tool form

```jsx
selectTool(reportBuilders[0].name); // BottomToolButtons
```

A report is generated by running its tool as a job, like any other tool - the Report Builder only picks the tool.

### DO: Fetch reports through `apiClient`, never navigate a tab to the route

A plain tab navigation carries neither the auth token nor the `X-CEA-*` scenario headers. `openReport` opens the
tab synchronously inside the click handler (so popup blockers allow it), then points it at a blob URL of the
fetched report.

### DON'T: Use hooks in `OpenReportButton`

It also renders inside antd's static `notification`, outside the app's providers - read cached data from the
query client in the caller instead (`queryClient.getQueryData(REPORT_BUILDERS_QUERY_KEY)`).
